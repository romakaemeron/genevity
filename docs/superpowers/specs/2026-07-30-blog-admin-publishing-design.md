# Публікація блогу з адмінки — production-ready

**Дата:** 2026-07-30
**Гілка:** `develop`
**Статус:** design approved

## Мета

Довести публікацію статей блогу з адмінки до продакшн-рівня: захистити server actions,
зробити помилки видимими, гарантувати появу змін на сайті одразу після збереження,
дати передперегляд чернеток, автогенерацію slug і автопереклад RU/EN.

Публічний блог **лишається прихованим на продакшні** — гейт `IS_PRODUCTION` у
`src/app/[locale]/(pages)/blog/page.tsx` та `[slug]/page.tsx` не змінюється. Уся
перевірка відбувається на preview-деплої гілки `develop`.

**Поза межами:** відкладена публікація за розкладом (свідомо відхилено — тільки ручна
публікація), редагування категорій блогу, коментарі, версіонування статей.

## Поточний стан

Адмінка блогу вже існує і здебільшого працює:

| Файл | Що там є |
|---|---|
| `src/app/(admin)/admin/blog/page.tsx` | Список статей |
| `src/app/(admin)/admin/blog/[id]/page.tsx` | Роут редактора, `id === "new"` = створення |
| `src/app/(admin)/admin/blog/[id]/_form.tsx` | Форма: WYSIWYG (Tiptap), SEO-прев'ю, медіа-пікер, рецензент-лікар |
| `src/app/(admin)/admin/blog/_actions.ts` | `savePost` / `deletePost` |
| `src/lib/db/queries/blog.ts` | Публічні та адмінські запити |

## Дефекти, які закриваємо

1. **Server actions без автентифікації.** `_actions.ts` не викликає `requireSession()`
   (на відміну від `press/_actions.ts`). Server action — це публічний HTTP-ендпоінт:
   будь-хто може створити, змінити або видалити статтю.
2. **Помилки збереження губляться.** `adminSavePost` повертає `{ ok: false, error }`,
   екшен цей результат ігнорує — форма просто нічого не робить.
3. **Немає унікальності slug.** Дві статті з однаковим slug ламають `/blog/[slug]`.
4. **Ревалідація не спрацьовує.** `revalidatePath('/blog')` не інвалідує
   `/[locale]/(pages)/blog` — сегмент `[locale]` динамічний, потрібна форма з шаблоном
   маршруту. Наслідок: при `revalidate = 86400` зміни видно лише за добу.
5. **Немає передперегляду чернеток.** `getBlogPostBySlug` жорстко фільтрує
   `is_draft = false AND published_at <= NOW()`.
6. **Майбутня дата публікації = мовчазне зникнення статті.**

## Дизайн

### 1. Автентифікація та валідація

`savePost` і `deletePost` починаються з `await requireSession()`.

Вхідні дані валідуються zod-схемою (zod уже в залежностях) у новому модулі
`src/app/(admin)/admin/blog/_schema.ts`:

- `slug` — `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`, 1–120 символів;
- `titleUk` — обов'язковий, непорожній після trim;
- `readTimeMinutes` — ціле 1–120;
- `publishedAt` — валідна дата; **якщо `isDraft === false` і дата в майбутньому —
  помилка** «Заплановану публікацію не підтримано…». Порожня дата при публікації =
  поточний момент. Минулі дати дозволені (бекдейтинг).

Помилка валідації повертається у формат `{ error: string, field?: string }` і не
змінює БД.

### 2. Видимі помилки у формі

`savePost` переходить на сигнатуру `(prevState, formData) => Promise<{ error?: string }>`
— патерн `useActionState`, який уже застосовано в
`src/app/(admin)/admin/pages/_components/page-form.tsx`.

- Успіх — як зараз: `redirect('/admin/blog/<id>?saved=1')`.
- Помилка — червоний банер над кнопкою збереження; введені дані лишаються у формі
  (клієнтський стан не скидається, бо redirect не відбувається).

`redirect()` кидає виняток керування потоком — важливо викликати його **поза**
`try/catch`, інакше він буде проковтнутий як помилка.

### 3. Унікальність slug

Нова міграція `src/lib/db/migrations/013_blog_slug_unique.sql`:
`CREATE UNIQUE INDEX IF NOT EXISTS blog_posts_slug_key ON blog_posts (slug)`.

Перед застосуванням перевіряємо наявні дублікати запитом `GROUP BY slug HAVING
COUNT(*) > 1`; якщо вони є — розв'язуємо вручну, а не мовчки перезаписуємо.
Таблиця маленька, тому `CONCURRENTLY` не потрібен.

`adminSavePost` ловить Postgres-код `23505` і повертає
`{ ok: false, error: 'Стаття з таким slug уже існує' }`.

### 4. Ревалідація

Новий хелпер `src/lib/revalidate-blog.ts`:

```ts
export function revalidateBlog() {
  revalidatePath('/[locale]/blog', 'page');
  revalidatePath('/[locale]/blog/[slug]', 'page');
  revalidatePath('/sitemap.xml');
}
```

Форма з шаблоном маршруту інвалідує всі локалі одразу — окремі виклики для
`/ru/blog`, `/en/blog` більше не потрібні.

Хелпер викликається з `savePost`, `deletePost` і з `/api/revalidate` (додається
entity `blogPost`), щоб логіка була в одному місці.

**Обов'язкова перевірка:** фактичну інвалідацію підтвердити на preview-деплої
(зберегти → оновити `/blog` → побачити зміну), а не покладатися на теорію.

### 5. Передперегляд чернеток

Next.js Draft Mode:

- `GET /api/admin/preview?id=<uuid>` — `requireSession()`, читає пост за id,
  `(await draftMode()).enable()`, редирект на `/blog/<slug>`;
- `GET /api/admin/preview/exit` — `(await draftMode()).disable()`, редирект назад
  у редактор;
- `getBlogPostBySlug(locale, slug, { includeDrafts })` — прапорець знімає фільтр
  `is_draft = false AND published_at <= NOW()`. Сторінка передає
  `includeDrafts: (await draftMode()).isEnabled`.

Draft Mode автоматично робить рендер динамічним і обходить статичний кеш, тому
`revalidate = 86400` передперегляду не заважає.

UI: кнопка «Переглянути» в редакторі (нова вкладка, лише для збережених статей) і
плашка «Режим передперегляду» з посиланням на вихід — на самій сторінці статті.

**Безпека:** ендпоінт увімкнення захищений сесією адмінки; cookie Draft Mode
видається лише після успішної перевірки.

### 6. Авто-slug

У формі: при введенні українського заголовка slug генерується транслітерацією
(офіційна українська латиниця, КМУ №55) у
`src/lib/slugify-uk.ts`.

Правила:

- працює лише для **нової** статті (`isNew`) — існуючий URL ніколи не змінюється сам;
- як тільки редактор торкнувся поля slug вручну, автогенерація вимикається до
  перезавантаження сторінки.

### 7. Автопереклад RU/EN

`src/lib/translate.ts` доповнюється функцією перекладу тіла статті зі збереженням
HTML-розмітки (структура тегів на виході має збігатися з входом; текст усередині —
перекладений).

Server action `translatePost(locale: 'ru' | 'en', payload)` — з `requireSession()` —
перекладає title, excerpt, seo title/desc і body з української версії й повертає
результат **у форму, не в БД**. Редактор бачить переклад, може виправити й лише потім
зберігає.

Кнопка «Перекласти на RU» / «Перекласти на EN» біля перемикача мов у редакторі,
зі станом завантаження та повідомленням про помилку (переклад ніколи не має валити
збереження).

## Перевірка

Тестового рантайму в проєкті немає, тому: `npm run lint`, `npm run build`, далі
наскрізний прогін на preview-деплої `develop`:

1. Створити статтю → збережено → одразу видно на `/blog` (без очікування доби).
2. Зберегти з дублем slug → зрозуміла помилка, дані у формі не втрачені.
3. Зберегти з майбутньою датою й статусом «Опубліковано» → помилка валідації.
4. Чернетка не видна на `/blog`, але відкривається через «Переглянути».
5. Вихід із передперегляду повертає звичайну поведінку (чернетка → 404).
6. Автопереклад заповнює RU/EN-поля, розмітка тіла збережена.
7. Видалення статті → зникає з `/blog` і з `sitemap.xml`.
8. Виклик `savePost` без cookie сесії відхиляється.
